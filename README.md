# МОС.ТРАМ — прогноз пассажиропотока

Веб-сервис для просмотра почасового прогноза посадок на трамвайных маршрутах Москвы. Проект состоит из Python/FastAPI API и React/TypeScript интерфейса с картой, фильтрами, графиками и выгрузкой CSV.

## Результат модели

- Прогноз: 1 ноября — 31 декабря 2025, полная сетка **10 маршрутов × 61 день × 24 часа = 14 640 строк**.
- Файл для загрузки: [`submission.csv`](submission.csv), разделитель `;`, UTF-8, поля `route;date;hour;prediction`.
- Метод: средний профиль посадок по комбинации `маршрут × день недели × час`, пропуски в исторической сетке считаются нулями. Использована общая калибровка 1,086, выбранная по двухмесячному отложенному периоду.
- Валидация Jan–Aug → Sep–Oct: **WAPE 0,1163; WAPE-score 0,8837**. Это результат внутреннего бэктеста, он не гарантирует такой же результат на скрытом периоде.
- У маршрута 5 в истории нет наблюдений. В прогнозе оставлены нули, как в базовом файле организаторов.

Пересобрать CSV и повторить бэктест:

```powershell
python model\forecast.py --backtest
```

Скрипт читает компактные разметки из `dataset\labels`, а не сканирует исходные CSV на 10 ГБ.

## Локальный запуск на Windows

В корне проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
cd frontend
npm install
npm run build
cd ..
python backend\build_map_data.py
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

Откройте `http://localhost:8000`. API и собранный интерфейс работают на одном порту. Для разработки с hot reload используйте два терминала: `.\run_backend.ps1` и `.\run_frontend.ps1`, затем откройте `http://localhost:5173`.

Карта использует тайлы OpenStreetMap, поэтому для подложки требуется доступ к интернету. Координаты в справочнике есть для маршрутов 1, 5, 7, 11 и 12; прогноз пассажиропотока строится по маршруту и часу, остановочной разметки в наборе нет.

## Docker

Сборка и запуск одного контейнера:

```powershell
docker build -t moskvy-tram-forecast .
docker run --rm -p 8000:8000 moskvy-tram-forecast
```

Образ включает API, готовый React build, компактные разметки и прогноз. Исходные `train.csv`/`test.csv` (около 10 ГБ без сжатия) исключены из образа. Для сервера предусмотрены два Uvicorn worker-процесса.

## API

| Метод | Назначение |
|---|---|
| `GET /api/health` | Состояние API и число предиктов |
| `GET /api/routes` | Маршруты и суммы посадок |
| `GET /api/forecast?start=2025-11-01&end=2025-11-30&granularity=day` | Дневные суммы по маршрутам |
| `GET /api/forecast?start=2025-11-01&end=2025-11-01&granularity=hour` | Почасовой прогноз за день |
| `GET /api/history?start=2025-09-01&end=2025-09-07&route=17&granularity=hour` | Почасовая история; широкий запрос ограничен для компактного ответа |
| `GET /api/history/weekday-average` | Исторические средние для сравнения с аналогичным днём недели |
| `GET /api/map` | GeoJSON вариантов маршрутов из справочника |
| `GET /api/export` | Исходный полный `submission.csv` |

`granularity=hour` ограничен 31 днём в общем запросе и 92 днями при выборе одного маршрута. Полный CSV выгружается напрямую без такой агрегации.

## Производительность

Обязательный локальный замер выполнен 25.09.2026 на Windows, Intel Core i5-12400F, 16 ГБ RAM, локальный Uvicorn API с одним worker-процессом. Метод: 32 запроса к каждому endpoint, 8 параллельных клиентов, loopback-интерфейс; измерялись полное время HTTP-запроса, включая тело ответа, и максимальная пропускная способность за серию.

| Endpoint / профиль | p50 | p95 | Макс. throughput |
|---|---:|---:|---:|
| Дневной прогноз за месяц (300 строк) | 14 мс | 28 мс | 476 RPS |
| Почасовой прогноз за день (240 строк) | 20 мс | 35 мс | 359 RPS |
| Почасовой прогноз: один маршрут/день (24 строки) | 10 мс | 28 мс | 583 RPS |
| Средние по дням недели (70 строк) | 5 мс | 21 мс | 774 RPS |
| Почасовая история за неделю одного маршрута | 29 мс | 37 мс | 257 RPS |
| История, дневная детализация (10 месяцев) | 110 мс | 136 мс | 70 RPS |
| Геоданные карты (45 КБ) | 8 мс | 18 мс | 734 RPS |

Сводные и выбранные почасовые запросы укладываются в целевые 200–300 мс и показывали сотни запросов в секунду на этом локальном стенде. Большая дневная история — отдельный более тяжёлый сценарий. RSS процесса после прогрева составлял около 126 МБ (один worker). Это замер без Docker, TLS, прокси и удалённой сети. Docker Engine на рабочем ПК во время замера не был запущен, поэтому контейнерный замер и профиль памяти контейнера ещё нужно снять на сервере.
